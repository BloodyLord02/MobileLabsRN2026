## Висновки
1. FlatList проти ScrollView: ScrollView одразу рендерить усі дочірні елементи, що призводить до нестачі пам'яті на великих масивах. FlatList рендерить лише видимі елементи, забезпечуючи високу продуктивність.

2. Віртуалізація списків: Це механізм оптимізації, за якого система відмальовує та тримає в пам'яті лише ті елементи списку, які в даний момент знаходяться у видимій області екрана користувача (включно з невеликим буфером).

3. Передача параметрів: Здійснюється шляхом передачі об'єкта з даними другим аргументом у функцію маршрутизації (navigation.navigate('НазваЕкрану', { параметри })). На цільовому екрані ці дані витягуються через об'єкт route.params.

4. Вкладена навігація: Це архітектурний підхід, за якого один навігатор вбудовується всередину іншого (наприклад, Stack Navigator виступає в ролі одного з екранів усередині Drawer Navigator), створюючи складну ієрархію переходів.

5. Використання SectionList: Застосовується для відображення даних, які необхідно згрупувати за логічними категоріями, де кожна група має свій власний заголовок (наприклад, список контактів, розділений на викладачів та студентів).
